# 2026 Game AI Study

게임 AI의 의사결정 구조와 강화학습의 원리를 이해하고, NYPC 같은 AI 경진대회에 도전하기 위한 개념적 기반을 쌓는 스터디입니다. 실습 구현 자체보다 **문제를 어떻게 정의하고, 어떤 AI 방법을 선택하며, 학습 결과를 어떻게 해석하는지**에 집중합니다.

## 공통 사례 — Top-down AI Survival Arena

모든 차시는 하나의 가상 탑다운 Arena 사례를 중심으로 설명합니다. 외부 에셋이나 실제 Unity 구현은 필수가 아닙니다.

| 요소 | 의미 |
| --- | --- |
| 에이전트 | AI가 행동을 결정하는 NPC |
| 출구 | 최종 목표 |
| 에너지 | 생존에 필요한 자원 |
| 위험 지대 | 피하거나 비용을 감수해야 하는 영역 |
| 장애물·경비병 | 판단을 복잡하게 만드는 환경 요소 |

이 사례를 통해 아래의 공통 구조를 반복해서 해석합니다.

```text
환경 → 관측 → 판단 정책 → 행동 → 상태 변화와 보상
```

## 12일차 개념 커리큘럼

| 일차 | 주제 | 강의에서 다룰 개념 | Arena 사례 질문 |
| --- | --- | --- | --- |
| 1일차 | 게임 AI 문제 정의와 Git/PR | 목표, 관측, 행동, 성공·실패 조건, 협업 흐름 | “무엇을 하면 탈출에 성공인가?” |
| 2일차 | 게임 환경과 에이전트 | 환경 상태, 부분 관측, 행동 공간, 게임 루프 | “NPC는 무엇을 알 수 있고 무엇을 할 수 있는가?” |
| 3일차 | FSM | 상태, 전이 조건, 상태 폭발, 디버깅 관점 | “언제 출구 이동에서 위험 회피로 바꿔야 하는가?” |
| 4일차 | Behavior Tree와 Utility AI | 우선순위, 선택자, 점수 함수, 상황별 의사결정 | “에너지와 출구 중 무엇을 먼저 선택할까?” |
| 5일차 | 탐색과 경로 계획 | 그래프, BFS, A*, 비용, 재계획 | “가까운 길과 안전한 길 중 어느 길이 좋은가?” |
| 6일차 | 강화학습의 출발점 | MDP, 에피소드, 정책, 가치, 탐험·활용 | “규칙 없이도 보상만으로 탈출을 배울 수 있을까?” |
| 7일차 | 보상 설계 | 희소 보상, shaping, 패널티, 보상 해킹 | “에너지 보상을 크게 주면 어떤 문제가 생길까?” |
| 8일차 | 가치 기반과 정책 기반 방법 | Q-Learning·DQN의 직관, 정책 최적화, Actor-Critic | “행동의 점수를 학습할까, 행동 확률을 학습할까?” |
| 9일차 | PPO 핵심 원리 | Actor, Critic, Advantage, Clipping, Entropy | “새 정책이 너무 급격히 바뀌면 왜 위험한가?” |
| 10일차 | PPO 학습 결과 읽기 | 평균 보상, 성공률, 분산, 과적합, 하이퍼파라미터 | “보상 그래프가 올라도 정말 잘 탈출하는가?” |
| 11일차 | 대회형 AI 전략과 검증 | 일반화, 랜덤 시드, 숨겨진 맵, 기준선, 재현성 | “처음 보는 Arena에서도 잘 동작하는가?” |
| 12일차 | LLM 에이전트와 AI 비교 | LLM의 고수준 계획, 제약된 행동, 규칙·RL·LLM 비교 | “LLM은 어느 판단을 맡고, 무엇을 맡기면 안 되는가?” |

## NYPC 수준을 위한 핵심 도달점

대회에 도전하려면 최소한 다음 질문에 답할 수 있어야 합니다.

- 환경의 관측·행동·목표·보상을 명확히 정의할 수 있는가?
- FSM, Behavior Tree, Utility AI, 경로 탐색의 적용 상황을 구분할 수 있는가?
- MDP와 정책, 가치, Actor-Critic의 역할을 설명할 수 있는가?
- PPO의 Advantage, Clipping, Entropy가 학습 안정성에 기여하는 이유를 설명할 수 있는가?
- 학습 보상과 실제 성공률이 다를 때 원인을 가설로 세울 수 있는가?
- 랜덤 맵이나 숨겨진 조건에서 일반화 여부를 검증해야 하는 이유를 아는가?

9~11일차가 경진대회 준비의 중심입니다. PPO 구현법을 암기하는 것보다, 보상·관측·평가 방식이 잘못됐을 때 어떤 현상이 나타나는지를 해석하는 능력이 중요합니다.

## 생성형 AI 사용 원칙

생성형 AI는 강의 내용을 대신 답하는 도구가 아니라 사고를 점검하는 도구로 사용합니다.

- 상태 전이 또는 보상 설계의 빠진 조건을 검토받습니다.
- 알고리즘의 장단점과 예상 실패 사례를 비교합니다.
- AI의 제안 중 반영한 내용과 제외한 이유를 기록합니다.
- 답변을 그대로 신뢰하지 않고 강의 개념과 사례로 검증합니다.
