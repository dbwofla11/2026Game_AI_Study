# 2026 Game AI Study

Unity에서 **에셋 없이 만드는 탑다운 AI 실험장**을 공통 프로젝트로 삼아, 규칙 기반 AI·강화학습·LLM 에이전트를 직접 구현하고 비교하는 스터디입니다.

## 공통 프로젝트 — AI Survival Arena

위에서 내려다보는 작은 경기장에서 NPC가 출구까지 살아남아 이동합니다. 모든 오브젝트는 Unity 기본 도형과 색으로 표현하므로 외부 에셋이 필요하지 않습니다.

| 요소 | 화면 표현 | 역할 |
| --- | --- | --- |
| 에이전트 | 흰 원 | AI가 조종하는 NPC |
| 출구 | 파란 원 | 도달하면 성공 |
| 에너지 | 초록 원 | 생존 시간 또는 점수 회복 |
| 위험 지대 | 빨간 영역 | 체력 또는 점수 감소 |
| 장애물 | 회색 사각형 | 이동을 방해 |
| 경비병 | 보라 원 | 접근하면 위험한 이동 오브젝트 |

게임의 목표는 단순히 출구에 도달하는 것에서 시작해, 에너지 관리·위험 회피·경비병 대응을 포함하는 생존 문제로 확장합니다.

```text
게임 환경 → 관측 → AI 판단 → 행동 → 게임 상태 변화
```

화면에는 항상 현재 목표, 선택한 행동, 상태, 이번 행동 보상, 누적 보상을 표시합니다. 학생은 AI가 왜 해당 행동을 골랐는지 관찰할 수 있어야 합니다.

| 일차 | 주제 | 핵심 실습 | 제출물 |

| 1일차 | AI 목표와 문제 정의 | 출구·에너지·위험이 있는 탑다운 환경의 목표, 관측, 행동, 성공/실패 조건을 설계한다. | `arena_goal.md`, 첫 PR |
| 2일차 | Unity와 AI의 연결 | 기본 도형으로 경기장을 만들고, NPC가 관측을 읽고 행동을 요청하는 흐름을 구현한다. | 실행 가능한 Arena 씬 |
| 3일차 | 규칙 기반 게임 AI | FSM으로 출구 이동, 에너지 획득, 위험 회피, 대기 행동을 구현한다. | FSM NPC와 상태 디버그 화면 |

| 5일차 | 보상 기반 게임 AI | 관측·행동·보상을 정의하고, 작은 Arena에서 강화학습 에이전트를 학습·분석한다. | 보상 설계표와 학습 결과 |
| 6일차 | LLM 에이전트와 검증 | LLM이 고수준 목표를 선택하게 하고, 같은 조건에서 FSM·Utility·학습 AI·LLM을 비교한다. | 테스트 결과 및 최종 PR |

## 일차별 상세 목표

### 1일차 — AI 목표와 문제 정의

코드를 작성하기 전에 AI가 해결할 문제를 정의합니다. 첫 버전에는 출구, 에너지, 위험 지대만 두고 경비병과 장애물은 이후에 추가합니다.

```text
목표: 제한 시간 안에 출구에 도달한다.
관측: 현재 위치, 출구·에너지·위험 지대의 상대 위치, 남은 에너지
행동: 상·하·좌·우 이동, 대기
성공: 출구 도달
실패: 시간 초과 또는 에너지 소진
평가: 성공 여부, 걸린 시간, 위험 진입 횟수
```

### 2일차 — Unity와 AI의 연결

게임 규칙은 Unity가 처리하고, AI는 관측을 바탕으로 행동만 결정합니다. 이동·충돌·승패와 AI 의사결정을 분리하는 구조를 만듭니다.

### 3일차 — FSM

`MoveToExit`, `GetEnergy`, `AvoidDanger`, `Wait` 상태와 전환 조건을 직접 설계합니다. 현재 상태와 전환 이유를 화면에 표시합니다.

### 4일차 — Utility AI

에너지 부족, 출구 거리, 위험도처럼 서로 충돌하는 목표를 점수로 바꿉니다. 가장 점수가 높은 행동을 선택하게 하며, 점수 변화가 화면에 보이게 합니다.

### 5일차 — 강화학습

같은 Arena에서 보상으로 행동을 학습합니다. 처음에는 다음처럼 단순한 보상으로 시작하고, 예상하지 못한 행동이 나오면 보상 함수를 수정합니다.

```text
출구 도달: +10
에너지 획득: +1
위험 지대 진입: -2
실패: -10
매 행동: -0.01
```

### 6일차 — LLM과 검증

LLM은 매 프레임 이동을 직접 조작하지 않고, `go_to_exit`, `get_energy`, `avoid_danger`, `wait`처럼 제한된 고수준 행동만 선택합니다. Unity가 선택된 행동의 유효성을 검사하고 실제 이동을 처리합니다.

마지막에는 같은 Arena와 랜덤 시드에서 네 가지 방식을 비교합니다.

- FSM, Utility AI, 강화학습 AI, LLM 에이전트의 탈출 성공률
- 평균 탈출 시간과 위험 지대 진입 횟수
- 에너지 소진 또는 시간 초과 같은 실패 원인
- 처음 보는 Arena 배치에서의 행동

## 생성형 AI 사용 원칙

생성형 AI는 답안을 대신 만드는 도구가 아니라 설계·구현·검증을 돕는 협업 도구로 사용합니다.

- 빠진 조건, 예외 상황, 상태 전이를 검토받습니다.
- 제안된 코드나 알고리즘의 동작을 설명받고 직접 검증합니다.
- AI 제안 중 반영한 내용과 제외한 이유를 PR 본문에 기록합니다.
- AI가 생성한 결과를 검증 없이 제출하지 않습니다.
