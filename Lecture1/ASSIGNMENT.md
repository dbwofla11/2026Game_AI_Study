# Lecture 1 과제 명세 — AI Survival Arena 목표 설계와 첫 Pull Request

## 목표

- Git의 기본 작업 단위인 `clone`, `branch`, `add`, `commit`, `push`를 사용한다.
- Pull Request(PR)로 과제를 제출하는 흐름을 익힌다.
- 탑다운 AI Survival Arena에서 NPC가 해결할 문제를 목표·관측·행동·평가 기준으로 정의한다.

## 준비물

- GitHub 계정
- Git 설치 환경
- 이 스터디 저장소에 접근할 수 있는 권한

## 과제 내용

1. 이 저장소를 자신의 컴퓨터에 clone한다.
2. 최신 `main` 브랜치를 기준으로 작업 브랜치를 만든다.
   - 브랜치 이름: `lecture1/깃허브아이디`
   - 예시: `lecture1/octocat`
3. `Lecture1/submissions/깃허브아이디.md` 파일을 작성한다.
4. 파일에는 아래 내용을 포함한다.
   - 이름 또는 닉네임과 GitHub 아이디
   - Arena의 목표
   - AI가 관측할 정보
   - AI가 선택할 수 있는 행동
   - 성공 조건, 실패 조건, 제약 조건
   - 화면 요소의 간단한 배치도 또는 설명
   - 평가 지표 2개 이상
   - AI에게 목표 설계를 검토받기 위해 사용한 질문 1개와, 제안을 반영하거나 제외한 이유
   - 이번 주에 사용한 Git 명령어 3개와 각 명령어의 짧은 설명
5. 변경 사항을 하나 이상의 의미 있는 커밋으로 남긴다.
6. 원격 저장소에 브랜치를 push한 뒤, `main` 브랜치로 향하는 PR을 생성한다.

## 제출 규칙

- PR 제목: `[Lecture1] 깃허브아이디`
  - 예시: `[Lecture1] octocat`
- PR 본문에는 작업 내용, 확인 방법, AI 활용·검토 기록, 질문 또는 리뷰 요청을 작성한다.
- 다른 사람의 제출 파일이나 기존 설정 파일은 수정하지 않는다.
- PR은 리뷰 또는 승인 후에 merge한다. 본인이 직접 merge하지 않는다.

## 완료 기준

- [ ] 지정된 브랜치에서 작업했다.
- [ ] 지정된 위치에 본인 제출 파일을 추가했다.
- [ ] 목표·관측·행동·성공/실패 조건을 모두 정의했다.
- [ ] 평가 지표와 AI 검토 기록을 작성했다.
- [ ] 커밋 메시지가 작업 내용을 알아볼 수 있게 작성되었다.
- [ ] `main`을 대상으로 하는 PR을 만들었다.
- [ ] PR 제목과 본문이 제출 규칙을 따른다.

## 제출 파일 예시

````md
# octocat

- GitHub: `octocat`

## Arena 목표 설계

- 목표: 에너지가 소진되기 전에 파란 출구에 도달한다.
- 관측: 현재 위치, 남은 에너지, 출구·에너지·위험 지대의 상대 위치
- 행동: 위, 아래, 왼쪽, 오른쪽 이동 또는 대기
- 성공 조건: 출구에 도달한다.
- 실패 조건: 에너지가 0이 되거나 60초 안에 탈출하지 못한다.
- 제약 조건: 빨간 위험 지대는 지날 수 있지만 에너지가 감소한다.

## 화면 배치

```text
NPC는 중앙에서 시작한다. 출구는 오른쪽 위에, 에너지는 왼쪽 위에,
위험 지대는 중앙과 출구 사이에 배치한다.
```

## 평가 지표

- 탈출 성공 여부
- 위험 지대 진입 횟수
- 남은 에너지

## AI 검토 기록

- 질문: "이 Arena 설계에서 빠진 예외 상황을 찾아줘."
- 반영: 에너지가 0이 되는 즉시 실패하도록 규칙을 추가했다.
- 제외: 위험 지대를 완전히 막자는 제안은 회피 판단을 실험하기 위해 적용하지 않았다.

## 사용한 Git 명령어

- `git status`: 현재 변경된 파일과 스테이징 상태를 확인했다.
- `git add`: 커밋에 포함할 파일을 스테이징했다.
- `git commit`: 스테이징한 변경 사항을 하나의 기록으로 저장했다.
````
