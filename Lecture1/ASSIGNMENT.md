# Lecture 1 과제 명세 — 미로 탈출 AI 목표 설계와 첫 Pull Request

## 목표

- Git의 기본 작업 단위인 `clone`, `branch`, `add`, `commit`, `push`를 사용한다.
- 다른 사람의 저장소에 직접 수정하지 않고, Pull Request(PR)로 변경 사항을 제안한다.
- 리뷰 의견을 반영해 PR을 업데이트하는 과정을 경험한다.
- 게임 AI를 구현하기 전에 목표, 관측, 행동, 성공 조건을 설계한다.

## 준비물

- GitHub 계정
- Git 설치 환경
- 이 스터디 저장소에 접근할 수 있는 권한

## 과제 내용

1. 이 저장소를 자신의 컴퓨터에 clone한다.
2. 최신 `main` 브랜치를 기준으로 본인 작업 브랜치를 만든다.
   - 브랜치 이름: `lecture1/깃허브아이디`
   - 예시: `lecture1/octocat`
3. `Lecture1/submissions/깃허브아이디.md` 파일을 새로 작성한다.
4. 파일에는 아래 내용을 포함한다.
   - 이름 또는 닉네임
   - GitHub 아이디
   - 미로 탈출 AI의 목표
   - AI가 관측할 정보
   - AI가 선택할 수 있는 행동
   - 성공 조건과 실패 또는 제약 조건
   - 텍스트로 표현한 작은 미로 맵 1개
   - AI에게 목표 설계를 검토받기 위해 사용한 질문 1개와, 제안을 반영하거나 제외한 이유
   - 이번 주에 사용한 Git 명령어 3개와 각 명령어의 짧은 설명
5. 변경 사항을 하나 이상의 의미 있는 커밋으로 남긴다.
6. 원격 저장소에 브랜치를 push한 뒤, `main` 브랜치로 향하는 PR을 생성한다.

## 제출 규칙

- PR 제목: `[Lecture1] 깃허브아이디`
  - 예시: `[Lecture1] octocat`
- PR 본문에는 다음을 작성한다.
  - 작업한 내용 요약
  - 확인 방법 또는 확인한 사항
  - 질문 또는 리뷰를 받고 싶은 부분(없으면 `없음`)
- 다른 사람의 제출 파일이나 기존 설정 파일은 수정하지 않는다.
- PR은 리뷰 또는 승인 후에 merge한다. 본인이 직접 merge하지 않는다.

## 완료 기준

다음 조건을 모두 만족하면 과제가 완료됩니다.

- [ ] 지정된 브랜치에서 작업했다.
- [ ] 지정된 위치에 본인 제출 파일을 추가했다.
- [ ] 커밋 메시지가 작업 내용을 알아볼 수 있게 작성되었다.
- [ ] `main`을 대상으로 하는 PR을 만들었다.
- [ ] PR 제목과 본문이 제출 규칙을 따른다.
- [ ] 리뷰 의견이 있다면 반영 후 다시 push했다.

## 제출 파일 예시

````md
# octocat

- GitHub: `octocat`

## 미로 탈출 AI 목표 설계

- 목표: 시작점 `S`에서 출구 `E`까지 제한 이동 횟수 안에 도달한다.
- 관측: 현재 위치, 상하좌우의 벽 여부, 출구 위치
- 행동: 위, 아래, 왼쪽, 오른쪽 이동 또는 대기
- 성공 조건: 출구 칸에 도달한다.
- 제약 조건: 벽을 통과할 수 없고, 30회 안에 탈출하지 못하면 실패한다.

## 미로 맵

```text
#########
#S..#...#
#.#...#E#
#########
```

## AI 검토 기록

- 질문: "이 미로 탈출 AI 설계에서 빠진 예외 상황을 찾아줘."
- 반영: 벽 충돌을 실패로 처리하는 대신, 현재 위치를 유지하도록 정했다.
- 제외: 랜덤 이동 제안은 다음 차시의 비교 요소로 남기기 위해 적용하지 않았다.

## 사용한 Git 명령어

- `git status`: 현재 변경된 파일과 스테이징 상태를 확인했다.
- `git add`: 커밋에 포함할 파일을 스테이징했다.
- `git commit`: 스테이징한 변경 사항을 하나의 기록으로 저장했다.
````
